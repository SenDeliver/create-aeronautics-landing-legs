Modrinth steps

  1. Make GitHub repo public (images in the description are raw.githubusercontent links).
  2. modrinth.com → sign in with GitHub → Create project → type Mod.
  3. Fill the shared metadata table. Description = paste publishing/modrinth-description.md.
  4. Upload icon + gallery images.
  5. Versions → Create version: jar, number 1.0.0, Release, NeoForge, 1.21.1, dependencies from the table, changelog from release notes.
  6. Submit for review. First review takes 1 to 3 days. Project URL becomes modrinth.com/mod/landing-legs.
  7. Settings → create a PAT with "Create versions" scope → GitHub repo secret MODRINTH_TOKEN.

CurseForge steps

  1. curseforge.com → Authors → Start a project → Minecraft → Mods.
  2. Name, slug landing-legs, summary, categories, license MIT, icon icon-400.png.
  3. Description: switch editor to Source/HTML and paste publishing/curseforge-description.html.
  4. Upload file: jar, display name Landing Legs 1.0.0, Release, 1.21.1 + NeoForge + Java 21, relations Create/Sable required, JEI/Jade optional.
  5. Submit. Note the numeric Project ID from the project page sidebar.
  6. API tokens page → create token → GitHub secrets CURSEFORGE_TOKEN and CURSEFORGE_PROJECT_ID.

After listing: releases are automatic

.github/workflows/publish.yml runs on every GitHub Release: builds the jar, pulls the latest ## [x.y.z] section from CHANGELOG.md as changelog, uploads to Modrinth + CurseForge + attaches to the GitHub release.

git tag v1.0.0 && git push origin main v1.0.0
gh release create v1.0.0 --title "Landing Legs 1.0.0" --notes-file publishing/release-notes-1.0.0.md

For 1.0.0 you can either upload by hand on both sites (steps above) or create the GitHub Release after the projects exist and the secrets are set, and let the workflow upload.
